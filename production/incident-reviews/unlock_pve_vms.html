2 Incident Log

2.1 INC-001 — 2025-03-14

Field Detail
VM ID 112
Node pve-node-02
Lock detected locked: backup
Root cause PBS network timeout during incremental backup at 02:17 UTC
Impact VM online but unmigrateable for ~40 min
Resolved by Manual lock clear via runbook after confirming no active vzdump task
Resolution time 40 minutes
Runbook followed Yes — unlock_pve_vms.py
Safety check passed Yes — no active vzdump task found

Timeline:

  • 02:17 — PBS reports connection lost mid-backup
  • 02:19 — Alert triggered: VM 112 migration fails on pve-node-02
  • 02:31 — On-call SRE identifies lock: backup in VM config
  • 02:45 — Runbook executed, safety check passed, lock cleared
  • 02:57 — VM successfully migrated, incident closed

Notes: > Backup network path between PBS and pve-node-02 flapped due to a switch > port reset. No data corruption observed. Dirty bitmap was invalidated and > next backup ran as a full backup automatically.

3 Recurring Patterns

  • Most incidents occur during the 02:00–04:00 UTC backup window
  • pve-node-02 has had the most occurrences — network path investigation pending
  • All incidents resolved without VM downtime

4 Preventive Measures Tracked

Measure Status
Increase PBS backup timeout threshold ✅ Done — set to 3600s
Add lock-detection alert in monitoring 🔄 In progress
Redundant network path for PBS traffic ❌ Pending

| Field | Detail |

| **Resolved by** | Manual lock clear via runbook after confirming no active vzdump task |

**Timeline:**
